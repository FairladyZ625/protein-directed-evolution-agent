## 零、为什么要换协议

48×6 那轮做完后发现一件事:**八个臂全部在第 2 轮就达到候选池真实最优 8.416205**,
之后四轮峰值一动不动。也就是 **67% 的预算花在答案已经找到之后**,
r3–r6 的任何策略差异按构造都无法体现在峰值上。

所以把每轮预算从 48 压到 12(总预算 288 → 72)重跑同一个 2×2,看协议是不是太容易。

## 二、复现了什么、没复现什么(这一节是重点)

### ✅ 复现了(换协议仍成立,这是真正的加强)

1. **v0.8 契约下批次逐位相同。** 两个协议、共 12 轮,反思开/关送测集合完全一致。
2. **v0.9 契约下批次分叉。** 两个协议都分。
3. **v0.9 反思臂在两个协议下都最好。** strong 160>158 / 42>39;
   复现率 19.6%<23.8% / 1.7%<10.0%。
4. **排除的 motif 全部来自证据,零凭空。** 两个协议、逐轮核对,零例外。

### ❌ 没复现的一条:「单给自主权反而更差」

48×6 里 v0.9 反思关臂比 v0.8 差(strong 153 < 158,复现率 28.3% > 23.8%),
我据此写过「自主权只有配上证据才有价值」。

**12×6 里这个形状消失了**:v0.9 反思关 = v0.8(39 = 39),复现率反而更好(6.7% < 10.0%),
后段更是和反思臂打平(都 2.8%)。

**这条不能写进报告。** 下面是查出来的原因。

## 三、为什么没复现:两个杠杆对批量的敏感度不一样

### 查证 1:小批量把标量杠杆量化掉了

`compose_batch` 里 `n_exploit = round(n * exploit_ratio)`。逐轮实测:

| 协议 | 臂 | 逐轮 `requested_ratio → n_exploit/n_explore` |
|---|---|---|
| 48×6 | v0.8 反思关 | 0.87→42/6 · 0.91→44/4 · 0.97→47/1 · 1.00→48/0 · 1.00→48/0 |
| 48×6 | v0.9 反思关 | 0.90→43/5 · 0.88→42/6 · 0.90→43/5 · 0.92→44/4 · 0.95→46/2 |
| 48×6 | v0.9 反思开 | 0.85→41/7 · 0.85→41/7 · 0.88→42/6 · 0.88→42/6 · 0.92→44/4 · 0.95→46/2 |
| **12×6** | **v0.9 反思关** | 0.90→**11/1** · 0.90→**11/1** · 0.90→**11/1** · 0.95→**11/1** · 1.00→12/0 |
| **12×6** | **v0.9 反思开** | 0.90→**11/1** · 0.90→**11/1** · 0.90→**11/1** · 0.90→**11/1** · 0.95→**11/1** |

**在 n=12 下,`[0.875, 0.958]` 整个区间都映射到同一个 11/1。**
agent 在 12×6 的反思臂里五轮都拿到 11/1——**它调了 ratio,但调了等于没调**。

把 agent 实际用过的区间 `[0.85, 1.00]` 量化一遍:

| 批量 | 可达的不同 `n_exploit` | 取值 |
|---|---:|---|
| n=48 | **8** 种 | 41, 42, 43, 44, 45, 46, 47, 48 |
| n=12 | **3** 种 | 10, 11, 12 |

**标量杠杆的分辨率随批量线性缩水。** 48×6 下它是活的,12×6 下它基本是死的。

### 查证 2:离散杠杆不受批量影响,而且它会被自发使用

`exclude_motifs` 是离散的,批量再小也不影响「这个 motif 排不排」。两个协议下它都在被用:

| 协议 | 臂 | 注入次数 | 实际排除 |
|---|---|---:|---|
| 48×6 | v0.9 反思关 | 0 | 无 |
| 48×6 | v0.9 反思开 | 5 | r2–r6 逐步累积到 20 个 |
| 12×6 | v0.9 反思关 | **0** | **r6 排除 `E2Q`** ← 没有卡片,自己决定的 |
| 12×6 | v0.9 反思开 | 5 | r3/r5/r6 排除 `N21D` `R5S` `T6Q` `D0K` |

**12×6 的反思关臂在零注入的情况下自己用了排除入口**——它从 `analyze_measured`
的实测数据里自行判断 `E2Q` 该排除。这是契约打开后出现的自发行为,48×6 那轮没有。

### 结论:那条「自主权有害」是标量杠杆的产物,不是自主权本身的性质

- 48×6:标量杠杆有 8 档分辨率 → agent 用它在后段保留了 4–7 个探索位
  (v0.8 的地板规则在那两轮会强制纯利用)→ 少拿 5 个 strong。
  **它是被自己调出来的探索税罚了,不是「自主」本身有害。**
- 12×6:标量杠杆只剩 3 档、实际恒为 11/1 → 它**没有机会**用这个杠杆伤到自己 → 39 = 39。
- 两个协议下都成立的是**离散证据入口**:v0.9 反思臂 strong 更高、复现率更低。

**可以写进报告的准确说法:**

> 两个杠杆对批量的敏感度不同。标量的 `exploit_ratio` 分辨率随批量线性缩水
> (n=48 下 8 档,n=12 下 3 档且实测恒定),因此基于它的任何结论都与批量绑定;
> 离散的 motif 排除入口不受批量影响,基于它的结论在两个协议下都复现。
> 先前「给自主权反而变差」的观察只在大批量下出现,应归因于标量杠杆的探索税,
> 而非自主性本身。

## 四、引用纪律(比上一版更严)

1. **跨协议不能比绝对复现率。** 48×6 的分母是 48/轮,12×6 是 12/轮,
   1 次复现在后者就是 8.3%。**只能比同协议内的臂间顺序**,那个顺序两边一致。
2. **峰值在两个协议下都饱和**,不能用来区分方法。达峰轮(r2 vs r4)可以用来说明
   协议难度,不能用来说明 agent 优劣——四臂的达峰轮在各自协议内都相同。
3. **strong 差仍然很小**(158/153/160 与 39/39/42),n=1,不能当效应量。
4. **「单给自主权反而更差」已被证伪为协议依赖,不得引用。**
5. 「批次逐位相同 / 分叉」与「排除集 ⊆ 证据集」是确定性事实,两个协议下都可独立复核。

## 五、第八章素材:改进建议与未来拓展

> 下面每一条都挂着本项目自己的证据,不是泛泛的展望。你可以直接取用,
> 也可以只取其中三四条展开。**建议优先取 1、2、3 三条**——它们是本项目独有的,
> 别处抄不到。

### 8.x-1 工具契约应当与提示词工程平级,作为一等设计对象

**证据**:v0.8 四臂 20 次 `compose_batch`,`agent_requested` 出现 **0 次**;
换契约后变成 **11/11**。同一个模型、同一个 seed、同一份注入内容,
批次从「逐位相同」变成「逐轮发散」。

**主张**:社区讨论 agent 能力时默认变量是模型与提示词,而本项目的实测显示,
**在提示词与模型都不变的情况下,仅改动工具签名就能让一个「毫无反应」的 agent
变成「持续响应证据」的 agent**。工具契约的表达力是 agent 自主性的上界,
应当与提示词一起进入实验设计,而不是当作固定基础设施。

**可操作的检查清单**(本项目踩出来的四条):
1. 提示词里有没有在劝退 agent 使用某个参数(「Prefer that default」);
2. 每轮的调用模板有没有把参数位省掉(agent 看不见的参数等于不存在);
3. 有没有硬规则恰好禁止证据所指向的那个方向(本项目的利用比地板);
4. **手上的参数能不能表达手上的证据**——标量 `exploit_ratio` 无法表达
   「别选带 N21D 的候选」,这是根因。

#### 一句可以直接当章节论点的话(CEO 拟,工程侧核过证据后微调)

> 智能体的「自主性」与「科研思维」表面上由大模型驱动,但其**物理上限**由底层环境的
> **工具契约(Tool Contract)**设定。契约狭窄僵化时,智能体退化为背书式的「叙述幻觉」——
> 它读证据、复述证据、然后交出与对照组逐字节相同的批次;只有当工具契约与科学证据
> **同构**(例如提供残基级的排除入口)、**且在实际批量下具备足够分辨率**时,
> 反思才能转化为真实的选样生产力。

**这句话的每一节都有本项目的实测支撑,但用词需要守住两条边界:**

1. **说「设定上限」,不要说「完全塑造」。** 我们证明的是:契约固定时,模型的贡献
   可以用哈希证明为零(v0.8 四臂逐位相同)。我们**没有变过模型**,因此不能推出
   「契约决定一切」。「上限」是我们证明了的,「全部」不是。
2. **「同构」是必要条件,不是充分条件。** 见下面 8.x-2:`exclude_motifs` 与证据同构
   且跨协议复现;`exploit_ratio` 即便解除了地板,在 n=12 下也会被量化成单一分配——
   **agent 调了参数,分配没变,而事件流里仍记录 `agent_requested`。**
   契约既要同构,也要有分辨率,否则自主性只剩表象。

「叙述幻觉」这个说法有硬证据:反思臂总结写过 "Residual reflexion excluded the two
strongly lethal round-5 contexts",而那一轮实测送测集合与对照臂**逐字节相同**。

### 8.x-2 杠杆的分辨率必须与批量匹配,否则自主性名存实亡

**证据**:`n_exploit = round(n × exploit_ratio)`。n=48 时 agent 用过的区间对应 8 档分配,
n=12 时只剩 3 档,且实测五轮恒为 11/1——**它调了参数,分配没变**。

**主张**:给 agent 一个连续旋钮时,必须核算它在实际批量下的**有效分辨率**。
分辨率不足时,agent 的决策会被静默量化掉,而事件流里仍然记录着
「agent_requested」,看起来像它在自主决策。**离散的、与批量无关的入口
(如 motif 排除)在这一点上更稳健**,本项目中它是唯一跨协议复现的杠杆。

### 8.x-2b 契约不是越宽越好:约束归环境,证据响应归 agent

**证据**:自主线一共 7 个工具,八个实验臂里 `check_knowledge` **一次都没被调用**。
查代码后确认 agent 是对的——我们把「查知识库」做成了可证明无用的动作:

1. 系统提示词规定的工作流只点名四个工具(`analyze_measured` / `best_so_far` /
   `compose_batch` / `test_composed_batch`),`check_knowledge` 不在其中;
2. 门禁说明写着「`compose_batch` 和 `list_pool` **已经只返回过门候选**」——
   对 `compose_batch` 的输出再查一遍,结果必然全过;
3. 唯一另一处提到它的地方是 `gate_rejected` 时的错误提示,八个臂里从未触发。

**但知识增强一直 100% 生效**:HD/BLOSUM 门禁在 `test()` 里无条件执行、不可绕过,
知识图谱的 rationale 由 `compose_batch` 主动推给 agent。**它是被环境强制执行的,
不是被 agent 查询的。**

**主张**:这说明「契约越宽 agent 越自主」是错的。真正的分界在于两类东西:

| | 应当放在哪 | 理由 |
|---|---|---|
| **约束的执行**(HD / BLOSUM / 终止密码子) | **环境**,不可绕过、不花预算、无裁量 | 做成可选就意味着 agent 可以跳过安全约束 |
| **证据驱动的选择**(排除已测致死 motif) | **agent**,需要与证据同构的入口 | 写死在环境里就是 v0.8 那个「读了证据、批次一字不改」的叙述幻觉 |

两个方向搞反都会出问题。完整的主张是:**该由环境保证的交给环境,该由证据驱动的
交给 agent,并给后者一个与证据同构、且在实际批量下分辨率足够的入口。**

**一个本项目没测的缺口(应在报告里承认)**:现有的知识消融 `--no-knowledge` 是把整个
门禁关掉,测的是「有没有知识」。**没有测过「门禁照常执行、同时让 agent 也推理知识」**
——比如把「该候选被拒是因为 BLOSUM 过于激进」回灌给它,看它下一轮的生成方向是否改变。
因此只能说当前设计自洽,不能说它最优。这是一个明确的下一步实验。

### 8.x-3 评测协议应当自带饱和检测

**证据**:48×6 下八个臂全部在第 2 轮达到候选池真实最优,67% 预算花在答案已找到之后;
压到 12×6 后达峰推到 r4,浪费降到 33%,但**四臂仍然同轮达峰**,峰值依然不区分。

**主张**:在多臂比较里,**主指标饱和 = 该指标失去区分力**,而饱和常被误读成
「都达到了最优」。协议设计时应当先检验主指标在预算内是否会饱和;
已经饱和时,应改用未饱和的过程指标。本项目改用**致死 motif 复现率**
(上一轮被测死的替换,这一轮还有多少候选带着它),它在两个协议下臂间顺序一致。

### 8.x-4 自述与行为必须分开审计

**证据**:反思臂的自然语言总结写过 "Residual reflexion excluded the two strongly
lethal round-5 contexts",而该轮实测送测集合与对照臂**逐字节相同**。

**主张**:agent 的自我叙述不构成行为证据。可执行的判据是
**送测集合的集合哈希**——它是唯一花掉真实预算的东西。建议把
「行为差异判据」写进任何 agent 评测的协议,并且该判据必须自带阳性对照
(本项目用采集档位的差异证明判据本身灵敏)。

### 8.x-5 未做的两项加分方向,以及为什么先不做

- **强化学习选择下一轮突变**:未实现。本项目的预算规模(288 / 72 次 oracle)
  不足以支撑策略网络的样本需求;在这个量级上,UCB 主动学习 + 上位感知代理
  已经能在第 2–4 轮命中候选池真峰,RL 的额外收益无法在实验里显现。
  **若要做,应先把协议改到主指标不饱和**(见 8.x-3),否则无法测出差异。
- **三维结构信息**:未实现。本项目做了保守位点分析(ESM-2 逐位熵)作为替代,
  并**如实展示了它的负结果**。引入结构需要 AlphaFold/ESMFold 推理与结构特征工程,
  属于下一阶段;当前的上位感知代理已经把真峰排名从第 2,776 位提升到第 429 位,
  结构信息的边际收益需要单独实验验证,不宜先验假设为正。

### 8.x-6 停止准则应当基于信息价值,而不是预算耗尽

**证据**:两个协议下都是「达峰后继续花掉 33%–67% 的预算」。

**主张**:以 EVI(批次信息价值)与实验成本比较作为停止判据,
而不是跑满预设轮数。需要明确效用函数、成本模型与预测校准;
**池内已知最大值不能作为真实实验的在线停止信号**(现实中不存在这个信息)。
达到工程阈值后应进入独立确认阶段。

### 8.x-7 连接真实自动化实验平台

已有 §8.4;可补一条本项目的具体接口设想:本系统的每一轮提名都以
**事件流 + 链式 SHA-256** 形式落盘,`agent.tool.test.residuals` 事件里已经包含
逐变体的提名时刻预测、实测值与残差。把 `test` 工具替换为实验平台的下单接口
(SiLA 2 / 实验室 LIMS),事件流的形态不需要改动——
**当前的「虚拟 oracle」与真实湿实验在契约上是同构的**,这是本架构可迁移的部分。

### 8.x-8 一个方法学教训,值得单列

**证据**:第一次 2×2 是无效的。采集策略挂在 `backtrack` 上的地方有两处
(系统提示词段落、`compose_batch` 的工具级默认),第一次只解耦了提示词层,
结果四个臂命令行看起来是 2×2、实际 `allocation_source` 全是同一档、批次逐位相同。

**主张**:**只修一层比两层都不修更危险**——实验看起来是受控的,其实不是。
凡「策略挂在某个开关上」的地方,动手前应 grep 该开关的全部读取点。
本项目已加双层守护测试并反向验证,比对脚本也改为取事件流里的实测档位而非命令行意图。
