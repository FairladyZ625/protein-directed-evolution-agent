已经落地的：随机基线（策略①，负对照地板线）

evolution/random_baseline.py 在真实 GB1 全表（149,361 个 4 位点变体，野生型 VDGV=1.0，全表最高 fitness 8.762）上跑了「冷启动 5000 池 + 3 轮、每轮均匀随机抽 96 个变体、查真值表当虚拟湿实验」的闭环。它不做择优，就是四方法对比里的第①条曲线，用来衬托后面三种策略。

「真值 oracle」＝直接查 GB1 实测 fitness 表，而不是用模型预测当评估器——这样评估不会自证，是这道题选 GB1 的核心好处。

  • 逐轮 top-10 均值：0.475 → 1.174 → 1.376（累计）；单轮命中率 22.9% → 27.1% → 27.1%。
  • 负对照 PASS：随机策略的 top-10 均值（约 0.5–0.8）远低于全表 top-1% 均值（3.304），说明查询逻辑无 bug、随机确实弱。
  • 5 个测试通过；同 seed 逐字节复现；跨 numpy/pandas 版本指标一致。锚点 commit 3483c84。

题目核心（⑤⑥）

四方法对比：这道题真正给分的地方

题目明确要求比较四种方法在同一预算下逐轮的 fitness 提升，并追问「LLM Agent 是真学到科学家思维，还是只是调用预测模型」。所以四策略必须同预算、同 oracle、同提名空间才可比，这由 T7 统一保证。

策略做法由谁
① 随机突变均匀随机提名（地板线）T1 ✓
② 模型直推T3 预测 top-k 贪心T7
③ LLM Agent五角色，无知识库T6+T7
④ 知识增强 Agent五角色 + 规则 + UCB 探索T6+T5+T7

一个要正面回答的智力风险

在 GB1 这种「整张地形都测过」的数据上，如果预测模型够好，策略②模型贪心其实很难被超过，策略③很容易退化成「给②的候选重新排序」——那就正好坐实了「Agent 只是在调模型」。

Agent 的增益必须来自②给不了的东西：不确定性下的探索（UCB 提升后几轮的样本效率）、知识约束避免把预算浪费在明显差的激进突变、以及跳出贪心因上位性卡住的局部最优。因此 T7 要测样本效率（固定 oracle 预算下找到的最优 fitness），而不只看终值。这层分析是 T9 失败案例章的骨料，也是区分度所在。
