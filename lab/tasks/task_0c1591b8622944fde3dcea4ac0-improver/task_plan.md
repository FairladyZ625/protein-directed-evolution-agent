# 外环最小可信一步:Improver 从残差自动生成排除列表,经沙箱回测才热更新内环

Task Contract: harness-task v1

## Brief

报告第 8.3 节的"五机双循环架构"目前是**纯设计图**:`improver` / `sandbox_gate` / `outer_loop` / `meta_evolution` 这些名字在仓库里 grep 只命中 `app/timeline_data.py` 的**展示文字**,没有任何实现。

本任务**不建整个双循环**,只让外环的一个环节产生可测收益:**Improver 从上一轮的逐变体预测残差自动生成排除列表 → 离线沙箱回测该列表 → 只有回测收益为正才热更新进下一轮的工具参数。** 目标是让第 8 章从"我们设计了一个架构"变成"这个架构里有一个环节跑通了,而且收益可测、可为负"。

## Goal

三个组件 + 一次端到端跑通 + 一个阴性对照:

1. **Improver**:输入上一轮的 `campaign.oracle.residuals` 事件,输出候选排除列表(一组 motif)与每条的生成依据(是哪些变体、哪个方向的残差支撑它)。
2. **SandboxGate**:用**历史已测数据**做离线反事实回测——"若上一轮采纳了这份排除列表,该轮的批次会变成什么、结果会更好还是更差",输出收益符号与数值。
3. **热更新路径**:仅当沙箱回测收益为正,才把排除列表写进下一轮工具参数;为负则丢弃并记录原因。
4. **端到端 + 阴性对照**:至少一次完整多轮运行,其中**必须包含至少一个沙箱判负、且确实没有热更新的轮次**。若始终没有判负的轮次,要构造一份必然有害的排除列表作为阳性对照,证明这道门真的会拦。

## Context

### 为什么选这个环节(不是随便挑的)

报告第 7 章里,本项目**唯一有正面证据的机制**是"工具契约能表达证据,agent 行为才改变":

- 旧契约下,强制注入上一轮残差后,**反思臂与对照臂六轮送测集合逐位相同(48/48 × 6)**,两种采集档位皆然;同期该臂的自然语言总结却声称已排除两个强致死背景。**读了证据、复述了证据、选样一字未改。**
- 换上能表达排除的契约后(同模型、同 seed、同注入文本):`agent_requested` 从 **0/20 变成 11/11**,送测集合逐轮分叉,排除列表从 0 增长到 20 个替换,每次请求都是此前累积卡片证据的子集。
- 卡片累计标记 **34** 个高估低适应度 motif,Agent 取其中 **20** 个进参数——是**选择性的**,不是一刀切。

**现在那条链的排除列表是人工强制注入的。** 本任务把它变成外环自动产生,并且加一道沙箱门决定是否采纳。这正好是"外环"在架构图里承担的职责(Memory → Improver → Sandbox → 热更新内环),而且是其中唯一一段已经有实测证据支撑的。

### 必须继承的两条诚实边界(报告里已经自曝,不能在本任务里悄悄丢掉)

1. **`motif` 的定义有局限**:它指"在已测低适应度变体中出现过的替换",**不等于它在所有背景中都不利**。所以"排除来源可追溯"只说明动作有依据,**不说明排除是对的**——是否排掉了有价值的组合,仍需结果与对照来评。本任务的 SandboxGate 正是为这条边界服务的:它是那个"用结果来评"的机制。
2. **沙箱回测是反事实,不是真实收益**:用历史已测数据评估"若当时排除了 X 会怎样",只能在**已测集合内**评估。报告与代码注释里都必须称其为"离线反事实回测",不得写成"实测收益"。

### 现成的地基(不用从零搭)

- **残差事件已存在**:`campaign.oracle.residuals` 记录逐变体的预测—测量配对。这条事件是后来补的;在它之前,**致命提名按定义永远进不了 top-10,每一个失败都是结构性没被记录的**。Improver 的输入就靠它。
- **契约改造已落地**:v0.9 的工具契约改造(`task_feb731c779788be5bfff65e979`,当前 in_review)已经把排除入口做出来了,`agent_requested` 这个字段就是它的产物。本任务是在那个入口**上游**接一个自动生成器,不需要再改契约形状。
- **事件流可自校验**:`EventStore.verify()` 能验链式哈希,端到端跑通后要用它验。

### 一个已知的陷阱

本仓已经踩过一次"注释诊断出机制、却没关上门"的坑(CI 门控清单连续三轮漏掉同一个测试文件)。所以本任务的验收标准里,**阴性对照是硬要求**:没有"沙箱判负且确实没更新"的证据,这个门就等于不存在。

## Implementation Plan

1. **读通残差事件的 payload 形状**,确认 Improver 需要的字段(变体序列、预测值、实测值、轮次)都在;缺则报回。
2. **实现 Improver**:从残差中挑出"高估且低适应度"的变体,统计其替换构成,产出 motif 候选列表 + 每条的支撑证据(哪些变体、残差多大)。保持与第 7 章相同的 motif 定义,并在代码注释里写明它的局限。
3. **实现 SandboxGate**:给定某轮的状态与一份排除列表,在**已测集合内**重算该轮会选出的批次,与实际批次比较目标指标,输出收益(正/负/零)与依据。明确标注这是反事实。
4. **接上热更新路径**:收益为正 → 写入下一轮工具参数;为负 → 丢弃并记录原因到事件流。
5. **定向测试**:
   - Improver 的输出对残差符号敏感(阳性对照);
   - Improver 对打乱真值标签**不变**(证明 answer-agnostic 的阴性对照);
   - SandboxGate 对一份人为构造的有害排除列表判负(证明门会拦);
   - 热更新在判负时确实不发生。
6. **端到端跑一次**多轮 campaign,记录每轮:Improver 产出了什么、沙箱判正还是判负、是否热更新、该轮结果。
7. **用 `EventStore.verify()` 验事件链**,并把逐轮记录写进报告。
8. 写报告落本任务包 `artifacts/`,包含"这一环有没有产生正收益"的诚实结论(可以是"没有")。

## Evidence Protocol

- 每条断言标明是**行为断言**(靠跑出红/绿)还是**结构断言**(靠 grep 两侧 + 读调用点)。
- **信一个检测器的沉默之前,先用阳性对照让它出声**:SandboxGate 判负的能力必须用人为构造的有害列表验证过,才可以相信它"没判负"是因为确实无害。
- answer-agnostic 用打乱标签的不变性测试证明,不靠代码走查断言。
- 端到端运行给出真实 runner 输出(预算花销、轮次、LLM 调用数、工具错误数),不摘录推理过程。
- 反事实收益一律标注为反事实;未验证的标 `unverified`。
