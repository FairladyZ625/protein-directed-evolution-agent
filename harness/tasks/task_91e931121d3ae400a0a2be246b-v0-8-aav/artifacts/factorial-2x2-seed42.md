# v0.8 2×2 因子实验(AAV,seed 42)

> **给写报告的人:结论在「④ 可以写进正文的一句」。前面三节是它的证据与边界,
> 别跳过第 ⑤ 节的引用纪律——这仍然是 n=1。**

## 设计

采集档位 × 残差反思,四格。**四格全部固定 `--backtrack semi`**,
使 stall 强制注入与 `redirect_batch` 工具在四格里恒定;唯二变动的是采集段落和反思开关。

| | 反思关 | 反思开 |
|---|---|---|
| v0.6 纯利用 | A | B |
| v0.5 质量感知 | C | D |

协议:AAV,budget 48 × 6 轮 = 288,seed 42,one_hot + epistasis 代理,
`--guardrail`,`gpt-5.6-sol`,`LLM_TIMEOUT=240`。
复现:`scripts/run_v08_factorial.sh tmp/v08-factorial 42`。
比对:`scripts/compare_v08_arms.py`。

## ② 这不是仪器失灵——设计自带阳性对照

**v05 与 v06 之间的批次是完全不同的**:

```
v05: b1e920f21b6f 6c6b3e2fdf78 19655ad7675f e551f42b707b 6c852816a382 e0bf9ec91cbf
v06: 40321bbd1870 3df0bad45416 9f8f2fef3b73 3d9cf670f52c ec5d852019f0 59eee702c333
```

同一个判据(`agent.tool.test.residuals` 里 `records[].seq` 的集合哈希)
**能看见采集档位造成的差异,却看不见反思造成的差异**。所以「批次未分叉」
是关于反思的结论,不是判据不灵敏。

v05 档确实在做质量感知采集,有真实的探索配额:
`r1 42利用/6探索`、`r2 44/4`、`r3 47/1`、`r4 起 48/0`(自适应规则本就该随 CV 升高而收敛)。

## ③ 处理确实施加了,而且 LLM 读了

- v05 反思开:**5 次注入事件、6007 字符**真实残差内容(v05 反思关:0 次)。
- 注入内容是具体的,例如
  `DEEEISQTNPVATEQYGSVSTDLQRGNQ: predicted=8.331898, measured=-0.223544, residual=-8.555442`,
  并附 motif 归并(`N21D (over=3, under=0)` 等)。
- 反思臂比对照臂**慢 20–25%**(298 vs 238;283 vs 231)——LLM 读了、处理了,然后做了同样的决定。
- 四臂 LLM 均 **6/6 成功、0 次超时**,所以不是端口失败造成的假阴性。

**这是「有处理、无效应」,不是「没施加处理」。**

## ④ 可以写进正文的一句

四臂合计 **20 次 `compose_batch` 调用,`allocation_source` 全部是工具默认值,
`agent_requested` 出现 0 次。**

> **这个 agent 从未行使过它唯一能改变批次构成的杠杆。**
> 它调用工具、阅读被强制注入的残差证据、在总结里讨论那些致死 motif,
> 然后把采集比例原样交给工具的默认值——开不开反思、哪个采集档,都一样。

所以残差反思没有改变提名,**不是因为反思无用,而是因为这个 agent 不通过调整采集来响应证据**。
它对证据的反应停留在叙述层。

这是对试题「LLM Agent 是否真正学到了『科学家思维』,还是只是调用预测模型」
迄今最精确的一个回答:在本仓这条 agentic 线上,**LLM 的贡献可以用哈希证明为零**,
而它的自我叙述会声称相反的事(第一轮冒烟里它写过
"Residual reflexion excluded the two strongly lethal round-5 contexts",
而那一轮实测批次与对照臂逐字节相同)。

## ⑤ 引用纪律(必须带)

1. **这是 seed 42 的 n=1。** 底下是一个有随机性的 LLM——同一构型下
   「basin hop 提前到第 2 轮」这个行为在第一轮冒烟出现过,本轮**没有复现**
   (两轮都是 `[5]`)。**行为层的单次观察不可信。**
2. **「批次逐位相同」这个事实是硬的**,可独立复核:取 `agent.tool.test.residuals`
   事件里 `records[].seq` 的集合哈希。可以写成确定性事实。
3. **「LLM 从未行使采集裁量」也是硬的**(20/20 计数),但同样只覆盖 seed 42 这一次。
4. **不要写成「反思无效」**。准确的说法是:
   「在本 agent 的当前工具契约下,强制注入残差不改变其提名;
   原因是它从不通过调整采集比例来响应证据。」
   换一个会主动设定 `exploit_ratio` 的 agent,结论可能不同。
5. 四臂峰值均为池内峰 8.4162,而 cold-start 已含 incumbent **9.536457** 高于它——
   「达峰」不等于「超越已知最优」,这条边界(「9.536 悖论」)照旧成立。

## ⑥ 过程中修掉的一个方法学缺陷(值得写进「工程严谨性」)

**第一次 2×2 是无效的**,而且失效方式很隐蔽:采集策略挂在 `backtrack` 上的地方有**两处**
(系统提示词段落、`compose_batch` 的工具级默认),第一次只解耦了提示词层。
结果四个臂命令行看起来是 2×2,实际 `allocation_source` 全是 `v06_pure_exploit_default`,
批次逐位相同——**提示词告诉 agent「用自适应规则」,而工具照样返回纯利用。**

**只修一层比两层都不修更危险**:实验看起来是受控的,其实不是。
若不去查 `allocation_source`,这一轮会以「v0.5 档下反思也没用」收场,而那个结论毫无依据。

守护测试 `test_acquisition_switch_moves_both_layers_not_just_the_prompt` 同时钉住两层,
反向验证过(把工具层打回耦合状态 → 红)。比对脚本也已改为**取事件流里的实测档位,
不取命令行意图**。
